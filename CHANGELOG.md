# Changelog

This document tracks the evolution of the ABOVE based RAG System from its initial prototype to the current production-ready version (v2.0.0).


## [2.1.2] - 2026-05-19
### Multilingual Support & Translation Architecture
### Language Detection:
Implemented automatic language detection using langdetect to identify the user's input language.
### Translation Nodes (RAG Engine):
Added translate_in_node to the start of the LangGraph workflow. Non-English queries are automatically translated to English.
Added translate_out_node to the end of the workflow. English responses generated by the system are dynamically translated back into the detected native language before being sent to the user.
Abstracted all language logic, mapping dictionaries, and LLM translation prompts into a dedicated core/translation.py module.
### Context Preservation:
Upgraded the API and UI to track and pass english_history alongside the native language history. This ensures that the reformulation_node and RAG generation nodes always have access to a clean, English-only conversation context, preventing mixed-language hallucination.


## [2.1.1] - 2026-05-14

### Guardrails & Output Enforcement

Added guardrails for out of bound queries.
Added guardrails for intent and extraction nodes for proper schema and format of response.


## [2.1.0] - 2026-05-08

### Major Observability, UI Guardrails & Boot Performance Upgrade

* **Core Engine & Boot Performance:**
    * **Local Volume Mapping Fix:** Corrected `docker-compose.yml` to properly mount the local Mistral AWQ model volume and aligned the `--served-model-name`, effectively reducing cold-boot times from ~6.5 minutes to `< 2 seconds`.
    * **Cold-Boot Request Buffering:** Implemented an `asyncio.Event()` lock in `main.py` that polls vLLM health on startup. The API now safely holds incoming user queries in a memory buffer while vLLM boots and profiles its KV Cache, completely eliminating startup `500 Internal Server Errors`.
* **Observability & Operational Transparency:**
    * **Process-Aware GPU Monitoring:** Upgraded `logger.py` to use `pynvml.nvmlDeviceGetComputeRunningProcesses`. The system now exclusively isolates and tracks the `VLLM::EngineCore` compute process VRAM footprint, ignoring host graphical (Xorg/GNOME) overhead for hyper-accurate reporting.
    * **Hierarchical CSV Logging Repair:** Fixed a directory mapping bug in `save_session_to_csv` to ensure all pipeline traces, history texts, and CSV metrics strictly write to the unified `/logs/sessions/{session_id}/{user_id}/{chat_id}/` nested structure.
* **Frontend & Reliability:**
    * **Strict UI Guardrails:** Overhauled `index.html` to lock UI interactions (disabling `createNewChat`, `switchSession`, and the send button) while the AI is generating, preventing duplicate request spam.
    * **Auto-Archiving:** Removed the manual save button. Deleting a chat now automatically forces a secure data dump to the backend CSV logs before wiping the chat interface.
* **Testing & CI/CD:**
    * **Parallel Stress Test Tracing:** Replaced the old load tester with `loop_stress_test.py`, introducing real-time client-side dispatch logs (`[CLIENT SEND]`) that sync seamlessly with the server's buffer ingestion logs (`[BUFFER IN]`) for end-to-end observability.
    * **Continuous Integration:** Added `.github/workflows/main.yml` to enforce Flake8 linting and Docker compose config validation on all pushes and PRs to `main` and `develop`.

## [2.0.0] - 2026-05-5

### Major Enhancements & Refactoring

* **VLLM Configuration:**
    * Updated the VLLM model source from `TheBloke/Mistral-7B-Instruct-v0.1-AWQ` to a local path: `/models/Mistral-7B-Instruct-v0.2-AWQ`.
    * Increased `max-model-len` to 4096 and `max-num-seqs` to 12 for better throughput.
    * Enabled `--enforce-eager` mode and explicitly defined the served model name as `mistral-local`.
* **Retrieval Pipeline (RAG Engine):**
    * Duplicate Filtering: Implemented a cosine similarity check (`util.cos_sim > 0.95`) in `retrieve_historical` to prevent redundant document chunks from being sent to the LLM.
    * Context Isolation: Enforced strict DB-level user isolation using `type::string(transcript.conversation.user) = $user_record`.
    * Graph Edge Mapping: Updated SurrealDB queries to use direct edge traversal (`->has_fact->facts`) to improve factual retrieval accuracy.
* **Logging System:**
    * Directory Structure: Refactored log paths to a hierarchical format: `/logs/sessions/{session_id}/{user_id}/{chat_id}/`.
    * Timezone Localization: Integrated `ZoneInfo("Asia/Kolkata")` to ensure accurate local timestamping across logs, CSV metrics, and detailed traces.
    * Detailed Traces: Added logic to log entire pipeline steps, including node-specific prompts, responses, and resource metrics.
* **Frontend (UI/UX):**
    * UI Modernization: Complete transition to Tailwind CSS with a dark-mode slate theme.
    * Chat Management: Introduced a dynamic `chat_id` system, allowing users to switch between multiple investigations in one session.
    * Session Persistence: Implemented robust session saving, manual export (CSV generation), and "keepalive" fetch requests to prevent data loss on tab closing.
    * Auth Flow: Added a persistent authentication modal with visual feedback (spinners) and error states.
* **Backend Stability:**
    * Increased `MAX_CONCURRENT_REQUESTS` to 60 for better scalability.
    * Implemented `asyncio.to_thread` and `ainvoke` throughout the graph nodes to prevent blocking the Event Loop during intensive LLM tasks.

## [1.3.0] - 2026-05-1

### Backend Integration & Optimization

* **Graph Logic:**
    * Formalized the `PipelineState` TypedDict to act as the single source of truth for variables across graph nodes.
    * Added dedicated `reformulation_node` with strict system instructions to force the LLM to output only the query text.
* **API Enhancements:**
    * Added support for `/session/close` to decouple session management from message handling.
    * Updated `main.py` to support `StreamingResponse` preparation and better concurrency limiting via Semaphore.
* **Model Prompting:**
    * Wrapped prompts in `[INST]` tags to comply with Mistral’s instruct template format, significantly improving instruction adherence.

## [1.2.0] - 2026-04-27

### Structural Overhaul

* **Directory Restructuring:**
    * Moved from a monolithic script file to a professional `app/core/` package structure (`engine.py`, `database.py`, `logger.py`).
* **State Management:**
    * Replaced linear graph flow with LangGraph states, allowing for conditional routing based on query complexity (using an `intent_node`).
* **Database Management:**
    * Encapsulated all SurrealDB logic inside a `DBManager` class, introducing standardized error handling and connection pooling/signin routines.
* **Containerization:**
    * Added custom Dockerfiles for retrieval and VLLM servers, utilizing `uvicorn` and `nvidia/cuda` base images to optimize GPU compute capabilities.

## [1.1.0] - 2026-04-22

### Initial Deployment & Dockerization

* **Environment Configuration:**
    * Introduced `docker-compose.yml` to define the relationship between the Retrieval API and the VLLM model server.
    * Added `extra_hosts` and networks to resolve `host.docker.internal` connectivity issues between container layers.
* **Memory Management:**
    * Added shell scripts in Docker commands to dynamically calculate `gpu-memory-utilization` based on available VRAM detected by `nvidia-smi`.

## [1.0.0] - 2026-04-17

### The Prototype

* **Core Functionality:**
    * Initial integration of LangGraph, SurrealDB, and SentenceTransformers for a standard RAG pipeline.
    * Basic manual logging to a shared `pipeline_metrics.csv`.
    * In-memory chat history tracking using local file-based persistence (`chat_history.txt`).
    * Basic langgraph nodes for intent classification (casual/factual/historical), basic metadata extraction, `llm_simple` generation, `llm_factual` generation and `llm_rag` generation.
